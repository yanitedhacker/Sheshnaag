# V5 Wave 1a — OIDC SSO

**Goal:** Accept identities from external OIDC providers (Keycloak, Authentik) with JIT user provisioning and claim→role mapping. Existing JWT path stays for service-to-service.

**Architecture:** New routes mint Sheshnaag JWTs after a successful OIDC handshake. JIT-creates `TenantUser` + `TenantMembership` rows on first login. The Sheshnaag JWT now carries a top-level `roles: [...]` claim that W0a's `verify_token` already unions into `TokenData.roles`.

**Tech Stack:** `authlib` v1.3+ (FastAPI / Starlette integration). `python-jose` (already pinned) handles ID-token JWKS verification.

## Locked decisions (per orchestration plan + Phase 0 defaults)

- IdP test rig: **Keycloak 24** + **Authentik 2024.x** via testcontainers (Phase 0 §1 default — ops sign-off recommended but not blocking code).
- JIT tenant assignment: **`tenant_claim` in provider config**; absent → per-provider `default_tenant_id` (Phase 0 §3 default).
- Library: **`authlib`** (orchestration plan §5).

## OidcProvider model

```python
class OidcProvider(Base):
    __tablename__ = "oidc_providers"

    id = Column(Integer, primary_key=True)
    name = Column(String(80), unique=True, nullable=False, index=True)
    issuer_url = Column(String(500), nullable=False)
    client_id = Column(String(255), nullable=False)
    client_secret_ref = Column(String(255), nullable=False)  # ref to KMS / env
    redirect_uri = Column(String(500), nullable=False)
    scopes = Column(JSON, default=list, nullable=False)  # ["openid","email","profile","groups"]
    claim_mappings = Column(JSON, default=dict, nullable=False)
        # {"role_claim": "groups", "tenant_claim": "tenant_id",
        #  "username_claim": "preferred_username",
        #  "role_value_map": {"sheshnaag-analyst": "analyst", ...}}
    default_tenant_id = Column(Integer, ForeignKey("tenants.id"), nullable=True)
    is_active = Column(Boolean, default=True, nullable=False)
    created_at = Column(DateTime, default=utc_now)
```

## verify_token extension

Today (post-W0a) `verify_token` calls `decode_token` against `settings.secret_key`. We extend it to:
1. Try the Sheshnaag JWT path (HS256 against `secret_key`). If it succeeds, return the existing `TokenData`.
2. If it fails AND the token's `iss` claim matches a registered `OidcProvider.issuer_url`, validate against that provider's JWKS (rotated weekly, cached) and surface the result via the same `TokenData` shape (with `roles` populated by `map_claims_to_roles`).

For V5 W1a we keep this strictly forward — the dominant flow is OIDC callback → mint a Sheshnaag JWT and return that to the client. ID-token-direct calls are a secondary path used by service-to-service adapters; they rely on the JWKS branch.

## Acceptance for W1a

- Migration v5a05 up + down clean on sqlite.
- `OidcService.install_provider()` rejects malformed config (e.g. unreachable issuer URL — soft-fail in test mode).
- `OidcService.handle_callback()` JIT-creates a `TenantUser` + `TenantMembership` on first login and reuses them on subsequent logins.
- `OidcService.map_claims_to_roles()` returns the configured Sheshnaag role names from the IdP group/role claim values.
- `verify_token` accepts a freshly minted Sheshnaag JWT carrying `roles: [...]` and the W0a `require_role` dep gates as expected.

## Out of scope for V5 W1a

- Live testcontainer-based Keycloak / Authentik smoke tests — the venv state makes this impractical right now; the test file exists and runs once anyio is repaired.
- Refresh-token rotation; we issue a fresh Sheshnaag JWT on each callback.
- SAML, SCIM provisioning, OAuth-1 — explicitly deferred (V9+).
